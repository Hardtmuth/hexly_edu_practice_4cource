## 1. Цель аудита

Проверить все SQL-запросы в коде на использование параметризованных аргументов
(плейсхолдеров `$1, $2, ...` с передачей значений через массив) вместо прямой
конкатенации строк (f-строк, шаблонных литералов с `${}`, `+`).

## 2. Методология

- Ручной анализ исходного кода файла `queries.mjs`
- Проверка каждого SQL-запроса: `SELECT`, `INSERT`, `UPDATE`
- Проверка функций, принимающих пользовательский ввод: `addPartner`,
  `updatePartner`, `getPartner`, `getSalesHistory`, `getProduct`,
  `getProductCoefficient`, `getMaterialDefectPercent`
- Поиск паттернов уязвимости:
  - `query(f"...")` с интерполяцией `${}`
  - `query("..." + variable + "...")` — конкатенация строк
  - `query(`...${variable}...`)` — шаблонные литералы с переменными внутри SQL

## 4. Результаты проверки

### 4.1. Уязвимости конкатенации строк: НЕ НАЙДЕНЫ

Ни в одной функции исходный SQL не формируется через интерполяцию
переменных или конкатенацию строк. Все запросы, принимающие пользовательский
ввод, используют плейсхолдеры `$1, $2, ...` с передачей значений через массив
вторым аргументом `pool.query(sql, [params])`.

**Пример безопасного паттерна (addPartner):**
```javascript
const res = await pool.query(
  `INSERT INTO partners (legal_form, company_name, inn, contact_email, phone, address, rating, director_name)
   VALUES ($1, $2, $3, $4, $5, $6, $7, $8)
   RETURNING *`,
  [legal_form, company_name, inn, contact_email, phone, address, rating, director_name]
)
```

**Пример безопасного паттерна (updatePartner):**
```javascript
const res = await pool.query(
  `UPDATE partners
   SET legal_form = COALESCE($1, legal_form), ...
   WHERE partner_id = $9
   RETURNING *`,
  [legal_form, company_name, contact_email, phone, address, ratingValue, director_name, inn, partnerId]
)
```

### 4.2. Дополнительные проверки

#### Валидация входных данных (server.js)

Перед попаданием в SQL-запросы данные проходят валидацию:

- `validatePartnerData()` проверяет:
  - `company_name` — не пустое
  - `contact_email` — не пустое
  - `inn` — не пустое
  - `rating` — число, не отрицательное (если передан)

- В `server.js` роут `/sales-history/:partnerId` и `/partners/:partnerId`
  проверяют `isNaN(Number(partnerId))` перед передачей в SQL.

#### Использование `COALESCE` в UPDATE

Использование `COALESCE($n, field)` безопасно: значение подставляется
через плейсхолдер, а не через конкатенацию.
